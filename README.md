# Arise Ecommerce

Enterprise-scale React Native (CLI) ecommerce application. JavaScript only, feature-based
vertical-slice architecture, designed for 10,000+ DAU and 5+ years of maintainability.

## Tech Stack

React Native CLI · Redux Toolkit + RTK Query · React Navigation · Axios · React Hook Form · Zod ·
Firebase · MMKV · Socket.io · Lottie · Reanimated · FlashList · Fast Image · Vector Icons · SVG

## Getting Started

```bash
npm install
npm run android   # or: npm run ios
```

## Project Layout (root)

| Path                           | Purpose                                                      |
| ------------------------------ | ------------------------------------------------------------ |
| `android/`, `ios/`             | Native projects (generated by React Native CLI)              |
| `src/`                         | All application code (see `docs/FolderStructure.md`)         |
| `assets/`                      | Static assets linked into native builds (fonts, images)      |
| `docs/`                        | Architecture and contribution documentation                  |
| `scripts/`                     | Dev/build tooling scripts                                    |
| `.env*`                        | Environment configuration (via react-native-config)          |
| `babel.config.js`              | Babel preset + `@` path aliases + Reanimated plugin          |
| `metro.config.js`              | Metro bundler config (inline requires for faster startup)    |
| `.eslintrc.js` / `.prettierrc` | Lint and formatting rules (enforced via Husky + lint-staged) |
| `index.js`                     | App entry point, registers `src/app/App.js`                  |

## Documentation

- `docs/Architecture.md` – architecture decisions and data flow
- `docs/FolderStructure.md` – responsibility of every folder
- `docs/CodingGuidelines.md` – coding rules (max 250 lines/file, one responsibility per file)
- `docs/NamingConvention.md` – file and symbol naming rules

## Core Rules

- No TypeScript, no Context API for business state, no business logic in screens.
- Screens → hooks → RTK Query/Redux → API layer → Axios. Never call Axios from a component.
- Features are isolated: import other features only through their `index.js`.
- Use `@` aliases (`@core`, `@shared`, `@features`, ...); never deep relative imports.
- No hardcoded values: use `src/constants` and `src/theme`.
